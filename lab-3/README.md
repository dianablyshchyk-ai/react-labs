Застосунок уже працює, але весь він — один компонент `App` у `src/App.jsx`.
Ви розкладете його на компоненти в теці `src/components/`, не змінивши
сторінки. Дані меню лежать у `src/data.js`, стилі — у `src/index.css`.

## Команди

`npm install` виконуйте в корені репозиторію `react-labs`, решту — у теці
`lab-3/`:

- `npm run dev`: dev-сервер на http://localhost:5173
- `npm run lint`: ESLint
- `npm run format:check`: перевірка форматування Prettier
- `npm run build`: production-збірка в `dist/`

## Стан

Для кожного рядка таблиці дайте відповідь на три питання з кроку 3 Thinking in
React (§4.7):

1. Чи залишаються ці дані незмінними з часом? Якщо так, це не стан.
2. Чи передаються вони від батьківського компонента через пропси? Якщо так, це
   не стан.
3. Чи можна обчислити їх на основі наявного стану чи пропсів? Якщо так, це
   точно не стан.

| Дані                                           | Стан? | Чому                                                                    |
| ---------------------------------------------- | ----- | ----------------------------------------------------------------------- |
| меню: категорії й позиції (`menu`)             | ні    | Передається згори через пропси з data.js і не змінюється під час роботи |
| текст у полі пошуку                            | так   | Змінюється користувачем під час введення і не може бути обчислений      |
| значення прапорця «Лише в наявності»           | так   | Змінюється користувачем при кліку та не може бути обчислений            |
| позиції, що залишаться після фільтрування      | ні    | Може бути обчислений з вхідного списку, тексту пошуку та прапорця       |
| кількість позицій у заголовку категорії, «(4)» | ні    | Може бути обчислена як items.length                                     |

Стан житиме в компоненті: App, бо він є найближчим спільним батьківським компонентом для SearchBar (який змінює стан) та MenuTable (який відображає відфільтровані дані).
