# ЛР-6. Робота зі складними формами та валідація

Стартовий проєкт лабораторної роботи № 6 курсу «Розробка вебзастосунків на
React»: форма бронювання столика з ЛР-5. Інструкція:
https://denysmatsevych.github.io/web-development-2026/react/labs/lab-6/

Форма працює так, як ви залишили її наприкінці ЛР-5, і перевіряє лише
обов'язкові поля (`required`). Ви опишете правила форми схемою Zod, передасте
значення полів React Hook Form, покажете повідомлення про помилки під полями
й надсилатимете бронювання на сервер через Action React 19.

## Що вже є

- форма з ЛР-5 (`src/components/BookingForm.jsx`) і контрольований
  `GuestsStepper`;
- нове поле «Телефон» і порожні абзаци для повідомлень про помилки під полями
  «Ім'я», «Телефон», «Дата» й «Час»;
- `src/api.js`: імітований сервер кав'ярні, який відповідає за секунду;
- `src/bookingSchema.js`: функції `today()` і `nowTime()` і порожня схема,
  яку ви заповните;
- стилі для повідомлень про помилки, стану очікування й форми підписки в
  `src/index.css`;
- бібліотеки `react-hook-form`, `zod` і `@hookform/resolvers` у
  `package.json`: `npm install` у корені встановить їх разом з іншими.

## Команди

`npm install` виконуйте в корені репозиторію `react-labs`, решту — у теці

## Порівняння з React Hook Form і Zod

### 1. Бібліотеки, версії та дати останніх релізів

| Роль                 | Основна версія (`lab-6`)                                               | Альтернативна версія (`lab-6-alt`)                      |
| :------------------- | :--------------------------------------------------------------------- | :------------------------------------------------------ |
| **Керування формою** | `react-hook-form` (`7.92.0`) — реліз у 2026 р. (активно підтримується) | `formik` (`2.4.9`) — останній реліз у листопаді 2025 р. |
| **Схема валідації**  | `zod` (`4.6.7`) — реліз у 2026 р. (активно підтримується)              | `yup` (`1.7.1`) — реліз у вересні 2025 р.               |

_(Примітка: у `lab-6-alt` пакет `zod@4.6.7` також залишився в залежностях, оскільки його використовує компонент `SubscribeForm` із §4.7)._

### 2. Відповідність API (що чим замінено)

| React Hook Form + Zod (`lab-6`)          | Formik + Yup (`lab-6-alt`)                                                                           | Призначення                                                                                  |
| :--------------------------------------- | :--------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------- |
| `register('name')`                       | `name`, `value={formik.values.name}`, `onChange={formik.handleChange}`, `onBlur={formik.handleBlur}` | Підключення стандартного поля `<input>` / `<textarea>` до форми та відстеження втрати фокуса |
| `<Controller name="guests" ... />`       | `value={formik.values.guests}` + `onChange={(val) => formik.setFieldValue('guests', val)}`           | Підключення кастомного контрольованого компонента `GuestsStepper`                            |
| `useWatch({ control, name: 'comment' })` | `formik.values.comment`                                                                              | Отримання актуального значення поля для лічильника символів (`0 / 200`)                      |
| `handleSubmit(onValid)`                  | `formik.handleSubmit` + колбек `onSubmit` в опціях `useFormik`                                       | Валідація форми перед відправкою та виклик обробника при успішній перевірці                  |
| `zodResolver(bookingSchema)`             | `validationSchema: bookingSchema` (схема `yup.object(...)`)                                          | Підключення зовнішньої схеми валідації до хука форми                                         |
| `reset()` + `setFocus('name')`           | `formik.resetForm()` + `formRef.current?.elements.name?.focus()`                                     | Скидання значень та стану помилок до початкових і повернення фокуса в перше поле             |

### 4. Ререндери під час введення в полі «Ім’я» (React DevTools → Highlight updates)

- **`lab-6` (React Hook Form):** під час друку в полі «Ім’я» **не ререндериться жоден компонент**. `register` працює через неконтрольовані DOM-посилання (`ref`), тому зміна тексту в полі не викликає оновлення стану React-компонента `BookingForm`.
- **`lab-6-alt` (Formik):** на кожне натискання клавіші в полі «Ім’я» **ререндериться весь компонент `BookingForm`**, а разом із ним і дочірній `GuestsStepper`. Це відбувається тому, що `useFormik` тримає значення всіх полів у внутрішньому стані React і оновлює його на кожну подію `onChange`.

### 5. Висновок: що обрати для наступного проєкту

Для наступного проєкту я обрала б пару **React Hook Form + Zod**. По-перше, React Hook Form забезпечує кращу продуктивність без зайвих ререндерів завдяки неконтрольованим полям та має зручні вбудовані інструменти на кшталт `setFocus` і `useWatch`, тоді як у Formik для автофокуса на першому невалідному полі довелося писати додатковий `useEffect` із DOM-пошуком, а сам пакет Formik не оновлюється з листопада 2025 року. По-друге, Zod має чистіший і сучасніший синтаксис для залежних перевірок між полями (через `.refine()` на рівні об'єкта) та забезпечує кращу типізацію без потреби використовувати `this.parent`, як у Yup.
